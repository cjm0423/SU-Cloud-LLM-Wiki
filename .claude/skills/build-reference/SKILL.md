# /build-reference — 흩어진 조회 자료 → 08_Reference 문서

개념 문서(`01_Concepts`)나 QnA·07 문서 곳곳의 `## 직접 확인해보기` 같은
**조회용 자료**(명령어·포트·설정값)를 모아 `08_Reference`의 정식
레퍼런스 문서로 만든다. Reference는 읽는 문서가 아니라 `Ctrl+F`로 값·문법만
찾는 조회 전용 문서다 → [[08_Reference/INDEX]].

## 0. 만들 값어치가 있는지부터 판단 (가드레일)

**개념마다 하나씩 만들지 않는다.** 태그를 23개로 통제하는 것과 같은 규율이다.

- **소스가 3곳 이상**에서 같은 주제의 조회 자료가 흩어져 있을 때만 만든다.
  1~2곳뿐이면 그 개념 문서에 그대로 둔다.
- **조회 자료인가**(값·문법을 찾음) vs **설명인가**(이해하려고 읽음)를 가른다.
  후자면 Reference가 아니라 `01_Concepts`의 몫이다.
- **환경 고유 조회표**(우리 노드/IP/포트 인벤토리)는 `08_Reference`가 아니라
  `07_SU-Cloud`에 둔다. 08은 도구 문법·명령 위주.

세 기준을 통과하지 못하면 문서를 만들지 말고 사람에게 그 이유를 알린다.

## 1. 흩어진 자료 수집

`Grep`으로 후보를 훑는다:
- `## 직접 확인해보기` 섹션을 가진 문서(`01_Concepts`, `07_SU-Cloud` 등)
- ` ```bash ` / `docker exec` / `openstack ` / 설정 파일 경로가 든 코드블록

주제별로 군집을 만들고, 각 명령을 **원본 그대로** 가져온다(요약·변형 금지 —
플레이스홀더 `<VM>`·`<NIC>` 등도 그대로). 근거 없는 명령을 지어내지 않는다.

## 2. 문서 작성 — `OKF-Reference-Template` 형식

`99_Templates/OKF-Reference-Template.md`를 그대로 따른다. 형식 규칙:

- **제목은 짧게.** 다루는 범위는 `## 이 문서로 조회하는 것`에 한 문장으로
  나열한다(제목에 `— A·B·C`를 붙이지 않는다).
- **항목 틀:** `**확인 대상**`(굵게) 다음 줄에 코드블록. 확인 대상 어미는
  동작 명사로 — 조회 / 확인 / 캡처 / 추가 / 식별. (`~인지`, `~하는 것` 금지)
- **실행위치는 코드블록 첫 줄 `#` 주석으로** (예: `# controller`, `# 호스트`).
  복붙하면 딸려온다. H2 제목이나 확인 대상 옆 괄호로 붙이지 않는다.
- 분류(H2)는 시스템 구조를 따라간다. 환경 고유 주의는 해당 분류 아래 `>`
  인용문으로 짧게.
- **관련 문서는 하단에 한 번만**, 성격별(개념 / 절차 / 사례 / 현황)로 한 줄씩.
  각 명령 항목에 개념 링크를 반복하지 않는다.
- **frontmatter:** `type: "reference"`, `status: "draft"`,
  `reviewed_by`/`reviewed_date`는 빈 문자열(승격은 `review-status` 몫).
  `raw_source`는 비우고, 값의 출처는 `related_nodes`(가까운 앵커 3~5개)로.
- **`tags`는 `TAXONOMY.md`의 23개에서만.** 축 D에 `#reference`는 없다 —
  `type`이 그 일을 하므로 만들지 않는다. 기술 스택 + 주제 영역 태그로 채운다.
- 파일명: `Keyword-English.md` (영문, 파스칼/케밥). `08_Reference/`에 둔다.

## 3. DRY — 정본은 한 곳

- 모은 명령이 개념 문서에 그대로 남아 중복되면, 개념 문서 쪽은 **대표 1~2개만
  남기고** 나머지는 이 레퍼런스로 링크하도록 정리한다.
- 어떤 개념에도 속하지 않는 일반 운영 명령이 다른 레퍼런스에 잘못 들어가 있으면
  올바른 문서로 옮긴다(예: 컨테이너/버전 조회는 네트워크가 아니라 클러스터).
- **`stable` 개념 문서의 본문을 대거 들어낼 때는** 무엇을 왜 옮겼는지 사람에게
  먼저 알린다 — 검토 이력이 있는 문서다.

## 4. INDEX.md 갱신

`08_Reference/INDEX.md`의 "수동 목록" 표에 새 문서 한 줄(파일·제목·태그)을
추가한다. Dataview 블록은 건드리지 않는다.

## 5. 커밋

새 문서 + INDEX 갱신 + DRY로 바뀐 개념 문서를 한 커밋으로 묶는다. 커밋 전
어떤 파일이 새로 생기고 바뀌는지 요약해서 보여준다.

커밋 메시지 형식: `docs: <레퍼런스 제목> 추가`

**push는 하지 않는다.** 사람이 확인 후 명시적으로 요청했을 때만 push한다.

## 하지 말 것

- 소스 3곳 미만인데 대칭성만으로 문서를 만들지 않는다(레퍼런스 남발 금지).
- 명령을 요약·변형하거나 근거 없이 지어내지 않는다 — 원본 그대로 옮긴다.
- 개념 링크를 각 명령 항목마다 반복하지 않는다(하단에 한 번만).
- `TAXONOMY.md`에 없는 태그를 만들지 않는다. `#reference` 태그도 만들지 않는다.
- 환경 고유 인벤토리(노드/IP/포트)를 08에 새로 만들지 않는다 — 07_SU-Cloud 몫.
